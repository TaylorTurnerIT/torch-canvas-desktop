# Agent notes for Torch Canvas (desktop fork)

This repository is a fork of [JesseTNRoberts/torch-canvas](https://github.com/JesseTNRoberts/torch-canvas) with a Tauri 2 desktop port. Read this file before changing code. README.md covers end-user behavior.

## What the repo contains

- **Upstream web app.** `src.html`, `core.js`, `engine.js`, `export.js`, and `library.js` are the sources. `node build.js` combines them with the example library into `index.html`. `server.js` serves the same files locally. Do not hand-edit `index.html`; it is generated.
- **Desktop layer.** `web/desktop.js` adapts the File System Access API calls to native Tauri commands. `web/index.html` is generated by `scripts/prepare-web.py`. Do not hand-edit it. `src-tauri/` holds the Rust shell. `tests/` holds the desktop test suites.
- **Upstream sources.** `src.html`, `core.js`, `engine.js`, `export.js` and `examples/` come from the original author, with provenance in `upstream/source.json`. The desktop build runs `node build.js` on them, so a change to those files reaches the desktop build after `npm run desktop:prepare`.

Both the web app and the desktop app must keep working. A change that only passes the desktop suites can still break `npm start` in a browser, and the reverse holds too.

## Desktop build pipeline

`scripts/prepare-web.py` runs `node build.js`, reads the resulting `index.html` and writes `web/index.html`. It makes these changes:

1. Replaces the dimension evaluator with `scripts/patches/eval-dim.js`. The evaluator uses an arithmetic parser, so the desktop Content Security Policy can run symbolic sizes without dynamic code compilation.
2. Inserts `scripts/patches/source-sync.js` inside the `NN` IIFE, before its `return`. It keeps marimo decorators and setup-cell imports on save, and it patches only changed code when the diagram changes.
3. Adds the variance size check, the native file-open reuse logic, the desktop save path, the Tauri credit, and the CSS and markup for the editor, marimo pane, and dividers.
4. Appends `scripts/patches/live-code.js`, `recents.js`, `marimo-pane.js`, `resizers.js`, and `open-files.js` at the end of the main app IIFE. The order matters.

The script raises an error if any anchor string does not match exactly once. If upstream changes, the script fails at that anchor. Fix the anchor and the patch together; do not loosen the match.

App globals live inside IIFEs, so a patch that needs `S`, `NN`, `renderCode`, or similar must sit inside the same IIFE. Two hooks exist for tests and the desktop shim:

- `window.torchCanvas = { state, commit }` is set in `live-code.js` for tests.
- `window.torchDesktop.handle` is set in `web/desktop.js`.

## Commands

| Command | What it does |
| --- | --- |
| `npm start` | Upstream web app: `node server.js` at http://localhost:5173 |
| `npm run build` | Upstream web build: `node build.js` produces `index.html` |
| `npm test` | Upstream tests: `node test.js` (round trips) |
| `npm run desktop:prepare` | `python3 scripts/prepare-web.py` produces `web/index.html` |
| `npm run desktop:dev` | `tauri dev` (runs `desktop:prepare` first) |
| `npm run desktop:build` | `tauri build --bundles app` produces `src-tauri/target/release/bundle/macos/Torch Canvas.app` |
| `npm run desktop:test` | `node --test tests/core.test.cjs` |
| `npm run desktop:test:ui` | Playwright in WebKit with a mocked `__TAURI__` bridge |
| `npm run desktop:test:native` | `cargo test` for `src-tauri` |

Run the suite that matches the change before committing. All suites that apply must pass:

- Changes to `core.js`, `engine.js`, `export.js`, `src.html`, or `library.js`: `npm run build`, `npm test`, `npm run desktop:prepare`, `npm run desktop:test`, and `npm run desktop:test:ui`.
- Changes to `scripts/patches/*` or `scripts/prepare-web.py`: `npm run desktop:prepare`, then `desktop:test` and `desktop:test:ui`.
- Changes to `web/desktop.js` or the editor UI: `desktop:test:ui`.
- Changes to `src-tauri/`: `desktop:test:native`.
- Changes to `tauri.conf.json` or capabilities: `desktop:test:native` and a `desktop:build`.

`desktop:test:native` does not run the ignored marimo test. That test starts a real `marimo edit` process and needs `uv` or `marimo` on PATH. Run it when you change marimo handling:

```sh
MARIMO_TEST_FILE=/path/to/notebook.py cargo test --manifest-path src-tauri/Cargo.toml -- --ignored marimo_runs_and_stops
```

Use `tests/fixtures/marimo-net.py` as the notebook.

The WebKit suite needs `npx playwright install webkit` once. It starts a static server on port 4173 from `web/`.

## Native side (`src-tauri/src/main.rs`)

- File access uses scoped grants. `native_pick` opens a native dialog and returns a handle. `native_read`, `native_write`, `native_entries`, and `native_child` operate only on granted paths. `checked_path` and `child_path` reject traversal and symlink escapes. Grants last for the process.
- `write_atomic` writes a temp file and renames it into place, so file watchers such as marimo never read a partial file. All saves go through it.
- Recent files: `remember` records the canonical identity of each file the user picked or opened, newest first, capped at 50, in `recent-files.json` under the app data directory. `native_reopen` reopens only identities in that list that still exist. Do not widen it to arbitrary paths.
- Files opened from Finder or `open -a` arrive as `RunEvent::Opened`. `grant_opened` grants them, queues them, and emits `torch-open`. The page calls `native_take_opened` on that event and once at startup (`open-files.js`).
- marimo: `marimo_start` and `marimo_stop` manage one `marimo edit` process per opened notebook.
  - It runs through a login shell (`$SHELL -l`) so `uv` and `marimo` resolve as in a terminal.
  - If the notebook has a `pyproject.toml` in an ancestor directory, it runs `uv run marimo edit`, adding `--locked` when `uv.lock` exists. Otherwise it runs `marimo` from PATH.
  - Flags: `--headless --no-token --watch --no-sandbox --skip-update-check --host 127.0.0.1 --port <random>`. The server listens on localhost only, without a token.
  - The process runs in its own process group, so stopping it signals the whole group. Startup waits up to 3 minutes for the port to accept connections.
  - `RunEvent::Exit` stops all running servers.
- `tauri.conf.json` sets the CSP. The page loads only local scripts and styles, with `style-src-attr 'unsafe-inline'` for SVG plots. `frame-src` allows `http://127.0.0.1:*` for the marimo iframe. Keep changes to the CSP minimal and test them under the UI suite, which uses the same nonce policy.

## Upstream relationship

- `origin` is this fork. `upstream` is JesseTNRoberts/torch-canvas. Keep pushes to `origin` public-safe.
- Merge from `upstream` rather than copying its files. Prefer putting features meant for upstream in its source files; `scripts/patches/*` is the desktop layer.
- Features meant for the upstream project belong in upstream's source files (`src.html`, `core.js`, `engine.js`, `export.js`, `library.js`). The patches in `scripts/patches/` hold only the Tauri and desktop layer.
- The project is MIT licensed. `LICENSE` and `NOTICE` must stay in place. The original Torch Canvas icon stays as shipped, and attribution to Jesse Roberts stays in the window title and the editor header.

## Conventions

- Keep personal machine details out of committed files: no home-directory paths, local machine names, or local setup notes. Use relative paths and placeholders in docs and tests.
- Commit messages and pull requests end with the attribution trailers used by this repository.
- The macOS app is signed ad hoc (`signingIdentity: "-"`) for local use. Developer ID signing and notarization are not configured.
- `index.html` and `web/index.html` are tracked, but both are build output. Regenerate them with `npm run build` and `npm run desktop:prepare`; do not edit them by hand. Do not commit `src-tauri/target/`, `src-tauri/gen/`, or `test-results/`.

## Working with marimo notebooks (for agents)

These rules describe how Torch Canvas writes a marimo `.py` file. They come from `scripts/patches/source-sync.js` and `live-code.js`.

- Edit the `.py` file directly. The app watches the open file every 1.5 seconds while the window is visible and redraws when the text changes on disk, unless the editor has unsaved changes.
- Model classes must be top-level `@app.class_definition` cells. The sync code recognizes only classes that start at column 0. A class nested inside an `@app.cell` is not treated as a model class.
- Imports belong in the `with app.setup:` block. When a regenerated class needs `torch`, `nn`, or `F` and the import is missing, the sync adds it to that block.
- Saving keeps unchanged code byte for byte. A diagram edit changes only:
  - `self.x = ...` statements in `__init__` whose generated value changed (new statements are inserted after the last related statement);
  - signature defaults and added or removed parameters;
  - the body of a method whose generated code changed. The original docstring is kept, and comments in that body are lost. `forward` is the usual case when the topology changes.
- Renaming the model renames only its class. Other code that refers to the old name is not updated.
- Methods the diagram does not touch are left as written, and so are comments, docstrings, extra methods, and training code outside the model classes.
- Only the active tab is watched. Switching files stops watching the previous one.
- There is no three-way merge. If the file changed on disk and the editor has unsaved changes, the file bar shows **changed on disk**. Saving then asks for confirmation and replaces the disk version with the editor text.
- Auto-save writes the file after an edit, but it does not overwrite a file that changed on disk. It sets the **changed on disk** state instead.
